# Necessidades identificadas

## 1. Origem e status

As necessidades abaixo foram derivadas do recorte documentado no repositório e das funcionalidades já demonstradas pelo protótipo. Elas são insumos para a especificação de requisitos de Bruna-Elisa.

Como ainda não existem entrevistas registradas, nenhuma necessidade abaixo deve ser apresentada como fala ou prioridade confirmada por usuário real.

## 2. Necessidades funcionais propostas

| ID | Necessidade | Prioridade proposta | Situação de validação |
|---|---|---|---|
| N-F01 | Compreender a distribuição de territórios e municípios em uma visão geográfica. | Essencial | Incluída no recorte técnico; validação humana pendente |
| N-F02 | Consultar pontos de interesse fictícios associados às áreas analisadas. | Essencial | Incluída no recorte técnico; critérios de prioridade pendentes |
| N-F03 | Visualizar representantes fictícios e respectivas áreas de cobertura. | Essencial | Incluída no recorte técnico; conceito de cobertura pendente |
| N-F04 | Identificar regiões sem cobertura e possíveis duplicidades. | Essencial | Incluída no recorte técnico; regras exatas pendentes |
| N-F05 | Planejar visitas demonstrativas sem persistir dados reais. | Essencial | Fluxo presente; critérios de planejamento pendentes |
| N-F06 | Comparar uma ordem de rota com uma sugestão local usando métricas explicáveis. | Essencial | Fluxo presente; métricas a validar |
| N-F07 | Consultar indicadores sintéticos para apoiar discussão de expansão. | Desejável | Incluída no recorte técnico; indicadores a validar |
| N-F08 | Demonstrar diferenças de acesso entre perfis acadêmicos. | Essencial | Matriz simulada existente; revisão dos perfis pendente |
| N-F09 | Informar claramente quando um dado é fictício, ausente ou ainda não confirmado. | Essencial | Regra transversal; teste de compreensão pendente |

As prioridades são uma proposta inicial. A decisão final pertence à equipe após entrevistas, testes e orientação do professor.

## 3. Necessidades não funcionais propostas

| ID | Necessidade | Justificativa acadêmica |
|---|---|---|
| N-NF01 | Isolar completamente o protótipo de sistemas e bancos empresariais. | Evita exposição de ativos, credenciais e dados operacionais. |
| N-NF02 | Usar somente dados sintéticos identificáveis como demonstração. | Protege pessoas e reduz o risco de confundir protótipo com produção. |
| N-NF03 | Explicar limitações, fontes e regras de cálculo. | Permite avaliação crítica e evita conclusões enganosas. |
| N-NF04 | Produzir resultados determinísticos nos cenários de teste. | Facilita reprodução, comparação e avaliação acadêmica. |
| N-NF05 | Manter navegação e textos compreensíveis para os quatro perfis simulados. | Sustenta a validação de usabilidade e acessibilidade. |
| N-NF06 | Tratar ausência de informação como dado ausente, não como valor zero. | Evita distorção dos indicadores. |
| N-NF07 | Revisar mudanças por Pull Request e preservar rastreabilidade. | Permite identificar autoria, decisão e evidência de validação. |
